# zherong-chatcut

把真实对话做成可审计、可继续编辑、可跨平台发布的短视频。保留人与 AI 之间的冲突、错误、纠正和真实反应，不把内容压扁成 AI 功能介绍。

## 强制约定

- 全程用中文向用户说明进度、判断、风险和结果；官方命令或插件名称可以保留原文。
- 人是主角，AI 或另一位说话者是固定对手或伙伴。
- 一条视频只交付一个承诺、冲突或可见的关系变化。
- 每次行动前刷新 ChatCut 实时项目、素材、转写和时间线；不得把旧交接快照当成当前事实。
- 保留所有已有时间线。不同结构、不同长度或不同方向的剪法，必须复制或新建时间线。
- 用户可见的剪辑留在 ChatCut 可编辑项目中，不用本地压平视频替代可编辑时间线。
- 未获明确授权，不导出、不发布、不覆盖旧版本、不购买或消耗生成额度。
- 个人资料、私聊、财务、关系、账号信息和原始素材默认不公开。
- 不伪造 AI 的回答、异常或人格表现；成功、失败、改口和翻车都可以成为真实内容。

## 需要加载的能力

开始实际剪辑前，先加载 ChatCut 基础能力，再只加载当前任务需要的能力：

- `chatcut:chatcut-plugin-basics`：定位项目与编辑器交接。
- `chatcut:talking-head-guide`、`chatcut:transcription`：口播 A-roll 与转写。
- `chatcut:voice`：消音哔声和其他音效；优先使用内置音效库。
- `chatcut:create-motion-graphics`：只有用户要求 MG 动画时才使用。
- `chatcut:verification`：报告可审结果前必须使用。
- `chatcut:export`：只有用户要求导出或下载时才使用。

需要当前平台选题或规则时，使用 Agent Reach 的当前可用后端进行只读研究。先运行 `agent-reach doctor --json`，再按结果路由；禁止点赞、关注、评论、发布和删除。

## 工作流程

### 1. 建立实时项目状态

从当前编辑器、项目列表或用户给出的链接确认目标项目。只读检查：

1. 项目名称与工作区。
2. 素材及转写状态。
3. 全部时间线、当前活动时间线和已批准版本。
4. 用户在其他电脑或手动完成的新增修改。

若无法访问目标项目，依次检查 ChatCut 插件、连接器授权、工作区归属和用户给出的项目链接。没有可靠目标时停止修改，但可以继续做选题、脚本或结构方案。

GitHub 只迁移 Skill 和公开资料，不迁移 ChatCut 登录、云端素材或时间线权限。

### 2. 定义一个观众承诺

用 `assets/templates/concept-card.md` 写概念卡。优先选择关系变化或可复现实验，而不是宽泛 AI 问题。

若任务涉及“小李／GPT Live”，先读：

- `references/current-topic-radar.md`
- `references/ready-to-record-experiments.md`
- `references/growth-strategy.md`

再用 `references/editorial-workflow.md` 评分并确定版本结构。需要最新爆款或平台规则时才刷新互联网证据，必须标注日期、样本和限制。

用户提供已导出视频、封面或完整发布包并要求评价时，先读 `references/export-cover-review.md`。这是审查任务，不强迫新建剪辑；先给结论和三项最高影响修改。撰写标题、正文、置顶评论或标签前读 `references/chinese-copy-voice.md`。

### 3. 检查素材与转写

- 先在项目素材池寻找目标文件，再向用户索要上传。
- 确认转写完成、说话人归属正确。
- 标记完整对话轮次、情绪反应、打断、停顿、错误、纠正和有效沉默。
- 重组前标记脏话及可能切到半个字的边界。

转写文字修正不等于音频剪辑。只有 ASR 识别错误时改转写；需要改变播放内容时使用 Script 编辑。

### 4. 先完成 A-roll

使用 ChatCut Script 工作流完成基于转写的选段与排序，保留完整语义和自然连接。

素材支持时默认产出：

- 主版：约 90–110 秒，一个完整关系弧。
- 短版：约 45–60 秒，同一承诺、更少证明节点。

时长是指导，不是配额。优先保留两到三次完整交换；AI 人格是主题时，可承担约 45%–58% 的有效对白，但每一句都必须增加判断、不确定性、纠正或行动。不要为比例保留废话。

应用 Script 后从头读回，修复逻辑断裂、重复观点、半字、黑场和呼吸异常。A-roll 稳定后再做音频平滑。

### 5. 按依赖顺序精修

1. 按 `references/audio-censor-sfx-qa.md` 完成脏话硬消音和音频检查。
2. 只在明确的编辑节点添加克制音效。
3. 生成或修复字幕；被消音文字统一显示为 `哔～`。
4. 仅添加用户要求的 B-roll、MG、音乐或特效。
5. 按 `references/platform-packaging.md` 制作封面和三平台发布包。

任何音效、字幕或图形都不能遮住最有价值的人脸、停顿和反应。

### 6. 验收后再报告完成

按 `references/completion-checklists.md` 和模板做结构与画面验收，不能只依赖工具返回成功。

至少确认：

- 前三秒能理解承诺，十秒内出现第一次情绪变化。
- 没有无升级的重复句。
- 说话人、对白顺序、字幕都正确。
- 没有意外叠音、半字、黑场或字幕溢出。
- 关闭哔声轨后，所有要求消音的原词完全听不见。
- 主版、短版和原版都保持独立可编辑。

精确报告三个状态：

- `演示就绪`：可编辑时间线与内部 QA 完成。
- `发布就绪`：用户确认含义、娱乐性与个人语气，包装完成。
- `已交付`：用户要求的导出完成，下载文件已验证。

## 用户审核只问三件事

1. 含义是否准确？
2. 关系或冲突是否有趣？
3. 是否仍然像用户本人？

用户要求低打扰执行时，除非遇到登录、权限、付费额度或重大创意分叉，否则先完成约定的整套工作再打断。
